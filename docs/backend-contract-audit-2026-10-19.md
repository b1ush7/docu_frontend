# 前后端接口核对（2026-10-19）

后续更新：上游已补齐全部 API 封装，当前扫描为 130 处调用封装、124/124 个接口匹配；下文“匹配度”保留首次核对时的数据。文件版本、会话恢复和转换任务的最新页面实现见 `high-priority-features.md`。

核对对象：当前 Vue 仓库的 `src/api`、工作台和管理端调用流程，以及文枢 Java 后端当前 Controller、DTO、VO 和服务实现。没有修改后端，也没有访问正式环境或发布前端。

## 匹配度

- 前端现有 **67 处 API 调用封装**，去重涉及 **61 个接口**：用户认证 13、文件与预览 16、异步任务 6、AI 会话与回复 11、管理端 15。
- 这 67 处封装的 HTTP 方法与路径均能匹配后端，扫描结果 **67/67**。这只说明路径契约存在，不能等同于全部页面已完成或真实业务联调全部通过。
- 后端共 **124 个方法与路径组合**（包含 Security LogoutFilter 的退出接口），当前封装覆盖 **61/124，约 49.2%**。未封装的 63 个接口属于功能覆盖缺口，不应通过新增后端接口解决。
- 参数、响应字段及状态语义由源码核对和下面的回归场景验证；不把 Mock 成功当作正式环境验收。

## 已修改

| 问题 | 修改后的行为 |
| --- | --- |
| 管理端 axios 没有 baseURL，生产构建可能请求前端域名 | 用户端、认证端和管理端统一读取 `VITE_API_BASE_URL` |
| 三套请求代码各自刷新，后端刷新令牌轮换时互相失效 | 共用刷新 Promise，旧访问令牌的迟到 401 复用新令牌；重放仍 401 则清空登录 |
| typed 刷新只更新 localStorage，Pinia 仍持旧令牌 | 刷新同步更新 store；管理端身份与普通用户端共用同一 store |
| 登录密码错误、刷新故障处理混杂 | 登录错误不刷新；刷新 503/网络故障保留凭据；刷新 401/403 清空并回登录 |
| 下载、页面图像请求的 JSON 错误被当成 Blob 文件处理 | 解析 JSON Blob，展示后端错误；正常二进制保持透传 |
| AI 同步调用默认 15 秒超时、超时重发生成新幂等键 | AI 生成等待 180 秒，确认等待 120 秒；同一意图网络失败后重试复用原版本与幂等键 |
| AI messageId 被作为 taskId 请求异步任务详情 | 两类 ID 分离，AI 编辑继续走会话回复与确认接口 |
| 确认成功立即退回输入页 | 保留明确输出版本的版面预览、比较和导出 |
| XLSX 确认结果调用 DOCX 结构接口 | 按输出版本格式分流；非 DOCX 使用通用版面预览 |
| 409 错误被 PENDING 分支遮住、按钮仍可重复确认 | 错误独立显示；禁用确认，仍可放弃并重新生成；提交/确认/放弃有互斥状态 |
| 图片插入、段落格式计划没有展示实际参数，操作标签使用旧码 | 补齐图片版本与尺寸、标题/列表/分页参数、批量格式及图片尺寸的中文说明，未知类型保留原文 |
| 无修改的普通 AI 回复没有显示 | 展示 AI 回复正文、核验提示和截断说明；失败或空差异不允许确认 |
| 版本比较及页面图像可能保留上个版本的异步结果 | 切换版本清空比较缓存，忽略过期页面/比较响应；页数未知时尝试首屏渲染后刷新元信息 |
| 管理端文件状态“全部”实际只查 READY | 去掉误导选项，按 READY / DELETED / QUARANTINED 明确查询 |
| 用户信息模块缓存跨账号残留，重新登录保留旧用户名 | 复用登录 store，登录前清除旧身份 |
| 验证码函数只检查长度 | 对齐后端数字 4～8 位规则 |
| 根 tsconfig 只有 references，原 type-check 未实际覆盖页面 | 显式检查 tsconfig.app.json，允许混合 JS 导入并修正暴露的类型错误 |
| CI 跳过类型检查 | 使用 npm ci、npm test 和 npm run build；SCSS 使用现有 sass 的 modern API |

请求头继续使用 `Authorization: <accessToken>`，没有 Bearer 前缀。所有文件修改仍遵循“生成待确认计划 → 确认 → 保存新版本”。新批量工具复用现有回复接口。

## 验证

```sh
npm ci
npm run type-check
npm test
npm run build
# 本机同时具有后端源码时，传入实际后端目录：
npm run check:api -- /path/to/documenter
```

14 项本地回归覆盖：跨请求栈并发刷新、密码错误、业务 401、重放失败、刷新暂时故障/失效、Blob 错误、store 同步、实际管理端封装、明确版本绑定、重复确认、XLSX 分流、409/放弃、幂等重试、失败/空计划和新修改类型展示。测试仅启动 127.0.0.1 模拟后端。类型检查与生产构建已通过；构建仍有既有大 chunk 提示。

## 尚未接入或尚未验收

- 上游已补齐接口封装，当前 `unwrappedRoutes` 为空；尚缺页面的功能包括 OCR、模板生成、人工 DOCX/XLSX 编辑、图片编辑及部分管理员高级功能。
- 版本历史、下载/恢复/比较、会话历史及计划恢复、转换/导出任务入口已在后续高优先级补齐中实现，详见 `high-priority-features.md`。OCR 和部分高级编辑仍没有对应完整页面。
- 上游已封装 SSE 流式回复，但当前 AI 页面仍走同步回复及必要轮询。
- 后端块级版本比较主要比较内容，不能据“无内容差异”判断字体或图片尺寸没变。排版变化应查看版面预览。
- 字体和排版预览依赖后端 LibreOffice、字体及转换配置。真实模型调用、跨域、正式环境登录与实际文档效果仍需部署后联调。
- `VITE_API_BASE_URL` 在构建时注入；生产地址变更需重新构建。现有 GitHub Pages base `/docu_frontend/` 和 SPA 回退保留。
